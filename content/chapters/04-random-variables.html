Random Variables

What a random variable is, how to build one from a bag-of-balls game, and why the choice of random variable depends on what you care about.

What is a random variable?

A random variable takes the outcome of a random experiment and turns it into a number. Instead of describing an outcome in words, like "you drew a red ball", you describe it with a number, like "you drew 1 red ball". Formally, a random variable is an association between the outcome of an experiment and a number. We usually write a random variable as a capital letter, such as X.

The bag of balls game

Here is a game. A bag has 5 balls: 3 red and 2 blue. You draw one ball, note its color, and put it back in the bag. You repeat this 4 times. Since the ball goes back in the bag each time, every draw has the same chances: 3 out of 5 for red, 2 out of 5 for blue.

If you get a red ball on all 4 draws, you receive ₹150. If you get any other pattern of colors, you pay ₹10. Would you play this game? To answer that, we go through three steps:

  1. Find all the possible combinations.
  2. Find the probability of each combination.
  3. Use the probabilities to estimate the profit or loss per player.

This chapter covers step 1, listing every outcome, and shows how to turn those outcomes into a random variable, which is what step 2 needs. Working out the actual probabilities is step 2, and comes in the next chapter.

Listing all the outcomes

Each draw gives either red (R) or blue (B), and you draw 4 times. So the number of possible color patterns is:

2 × 2 × 2 × 2 = 24=16

Here are all 16 patterns, grouped by how many red balls they contain. For example, in the "1 red, 3 blue" group, the single red ball could land on the 1st draw, the 2nd draw, the 3rd draw, or the 4th draw, giving 4 different patterns: RBBB, BRBB, BBRB, and BBBR.

These 16 patterns are not equally likely. Red comes up more often than blue on each draw, so patterns with more red balls are more likely than patterns with fewer. Working out exactly how likely each one is comes in the next chapter.

Turning the outcomes into a random variable

Now define the random variable for this game. Let X be the number of red balls in the 4 draws. To find X for any outcome, look at the 4 draws in order and count how many of them are red.

Worked example: take the outcome RBBB (red, blue, blue, blue).

  • Draw 1 = R (red)
  • Draw 2 = B (blue)
  • Draw 3 = B (blue)
  • Draw 4 = B (blue)

Only draw 1 is red. That is 1 red draw out of the 4, so X = 1 for this outcome.

X does not care about the order of the colors, only the count. So every pattern in a row of the earlier table maps to the same value of X:

X (number of red balls)01234
Number of outcomes14641

Why this random variable, and not another one?

Number of red balls is not the only way to quantify these outcomes. For the same experiment, you could just as easily define:

  • the number of blue balls drawn, or
  • the number of red balls minus the number of blue balls.

Take the outcome blue, red, red, red as an example. Write out each of the 4 draws in order first:

  • Draw 1 = blue
  • Draw 2 = red
  • Draw 3 = red
  • Draw 4 = red

Now count for each definition:

  • Number of red balls: draws 2, 3, and 4 are red. That is 3 draws, so X = 3.
  • Number of blue balls: only draw 1 is blue. That is 1 draw, so this variable = 1.
  • Red balls minus blue balls: 3 red draws minus 1 blue draw, so 3 − 1 = 2.

All three are valid random variables, since each one is a clear rule that turns any outcome into a number. None of them is more "correct" than the others in general.

Which one you pick depends on what you actually care about. In this game, the payout rule only depends on how many red balls you drew (all 4 red wins, anything else loses), so number of red balls is the useful choice here. That is why we defined X that way.

For the outcome red, blue, red, blue, what value would each of these three random variables take: number of red balls, number of blue balls, and red balls minus blue balls?

First, write out each of the 4 draws in order:

  • Draw 1 = red
  • Draw 2 = blue
  • Draw 3 = red
  • Draw 4 = blue

Now count for each definition:

  • Number of red balls: draws 1 and 3 are red. That is 2 draws, so this variable = 2.
  • Number of blue balls: draws 2 and 4 are blue. That is 2 draws, so this variable = 2.
  • Red balls minus blue balls: 2 red draws minus 2 blue draws, so 2 − 2 = 0.

In the bag game, what values can the random variable X (the number of red balls) take, and how many of the 16 outcomes give each value?

X can be 0, 1, 2, 3, or 4, since with 4 draws you can never have fewer than 0 or more than 4 red balls. The outcome counts for each value, from the table above, are 1, 4, 6, 4, and 1.

Add these counts together:

1 + 4 + 6 + 4 + 1= 16

This matches the total number of outcomes, 16. It has to match, because every single one of the 16 outcomes has some exact number of red balls between 0 and 4, so each outcome is counted in exactly one of these five groups, never in two groups and never in none.

You win the ₹150 prize only if you get a red ball on every draw. In terms of X, what condition is that, and how many of the 16 outcomes satisfy it?

Getting a red ball on every one of the 4 draws means all 4 draws are red, which is exactly X = 4. Looking back at the outcomes table, only one pattern has all 4 draws red: RRRR. So only 1 of the 16 outcomes satisfies X = 4. The other 15 outcomes all have at least one blue draw, so X is 3 or less for those, and they all mean you pay ₹10 instead.

Random variables outside the game: predicting loan defaults

The same idea shows up far beyond bags of balls. Say you are a data analyst at a bank, trying to predict which customers will default on their loan, meaning they stop paying it back. You have this data:

CustomerYearly incomeLoan dueDependentsDefault prediction
1₹10 lakh₹75 lakh3Yes
2₹15 lakh₹50 lakh2No
3₹20 lakh₹40 lakh1No

The "Default prediction" column is Yes or No, which is words, not numbers. Define a random variable X for it:

X = 1, if the customer is predicted to default
X = 0, if the customer is not predicted to default

The table now becomes fully numeric:

CustomerYearly incomeLoan dueDependentsX
1₹10 lakh₹75 lakh31
2₹15 lakh₹50 lakh20
3₹20 lakh₹40 lakh10

Once every column is a number, it becomes possible to perform statistical analysis on the data that words like "Yes" and "No" would not allow.

Look at Customer 2 in the table above: their Default prediction is No. Using the rule X = 1 for default and X = 0 for no default, what is X for Customer 2?

Customer 2 is predicted not to default, so X = 0. This matches the converted table above.

We have now finished step 1 (listing every outcome) and set up the random variable X that step 2 needs. Step 2, working out how likely each value of X actually is, turns this table of counts into a full probability distribution, and comes in the next chapter. Step 3, using those probabilities to work out whether this game is worth playing, comes after that.
