TensorBox

An all-in-one production environment for Machine Learning, MLOps, Deep Learning, and LLM Engineering, built and published by Ankit Surana.

TensorBox is a standardized, multi-architecture container environment covering Machine Learning, Deep Learning, Natural Language Processing, Large Language Models, and MLOps engineering. Instead of installing dozens of libraries and tools yourself, you pull one image and everything is already set up and ready to use.

Full listing and tag history: hub.docker.com/r/ankitsurana/tensorbox

System requirements

  • Supported OS: macOS (Apple Silicon or Intel), Linux (Ubuntu, Debian, RHEL), Windows 10/11 (via WSL2)
  • Architecture: linux/amd64 and linux/arm64 (multi-arch, works on both Intel and Apple Silicon)
  • Container engine: Docker Engine 20.10+ or Docker Desktop 4.0+
  • Hardware: 4 GB RAM minimum (16 GB recommended), 2+ CPU cores, 8 GB free disk space
  • GPU acceleration (optional): an NVIDIA GPU with the NVIDIA Container Toolkit installed

Quick start

Pull the image once:

# Pull the container image
docker pull ankitsurana/tensorbox:latest

Then launch whichever tool you need. JupyterLab:

# Web UI on http://localhost:8888
docker run -d --name tensorbox-jupyter -p 8888:8888 -v $(pwd):/workspace ankitsurana/tensorbox:latest jupyter

Or VS Code, running in your browser:

# Web UI on http://localhost:8080
docker run -d --name tensorbox-vscode -p 8080:8080 -v $(pwd):/workspace ankitsurana/tensorbox:latest code-server

Or drop into an interactive terminal with every port mapped at once:

docker run -it --rm -p 8888:8888 -p 8080:8080 -p 5001:5000 -p 8501:8501 -p 6006:6006 -v $(pwd):/workspace ankitsurana/tensorbox:latest

Note the 5001:5000 mapping in that last command: on macOS, port 5000 is already used by AirPlay Receiver, so the container's port 5000 (FastAPI) is mapped to 5001 on your machine instead, to avoid a conflict.

In every command, -v $(pwd):/workspace mounts your current folder into the container, so any files you create in /workspace are saved on your own machine, not lost when the container stops.

Inside the container: the tensorbox command

Once you're in the interactive terminal, a single command handles everything:

tensorbox status # Inspect system resources, Python version, and installed libraries
tensorbox jupyter # Start JupyterLab on port 8888
tensorbox code-server # Start VS Code Web on port 8080
tensorbox fastapi [app.py] # Launch FastAPI with Swagger docs on port 5000
tensorbox streamlit [app.py]# Launch a Streamlit dashboard on port 8501
tensorbox test # Run the test validation suite

Pre-installed directories

Reference implementations, production project templates, and datasets are already packaged inside the container under /opt/tensorbox:

  • /opt/tensorbox/notebooks/ — worked implementations for Classic ML, Deep Learning, NLP, LLMs, RAG, Time Series, MLOps, and Explainable AI
  • /opt/tensorbox/projects/ — production-style implementations for Feature Stores, Model Serving APIs, Drift Monitoring, and LoRA/QLoRA Fine-Tuning
  • /opt/tensorbox/data/ — benchmark datasets ready for immediate experimentation

Copy any of these into your own mounted workspace so they persist outside the container:

cp -r /opt/tensorbox/notebooks /workspace/
cp -r /opt/tensorbox/projects /workspace/
cp -r /opt/tensorbox/data /workspace/
